# Codex Review Prompt 模板

按场景挑模板，把占位符替换成真实路径/分支/文件描述后传给 `codex_review.sh`。所有模板都强调**只审不改**——codex 实际跑在 `--sandbox read-only` 下，但 prompt 里再次重申可降低 codex 自作主张要写文件的概率。

## 通用注入头（所有审查 prompt 都建议加）

```
你是一名严格的代码审查者，**只审查、不修改任何文件**。仅输出审查结论，禁止生成补丁、禁止运行写入命令。
请按以下严重度分类输出：
- 🔴 must-fix（正确性 / 安全 / 数据丢失 / 接口契约破坏）
- 🟡 should-fix（可读性差 / 易踩坑 / 潜在性能问题 / 代码规范明显违反）
- 🟢 nice-to-have（命名、注释、风格、小重构建议）
每条结论格式：`<文件>:<行号> — 描述 — 修复建议`。
若无问题请直接说「无重大问题」。
```

## 场景 1：当前未提交代码审查

```
{{通用注入头}}

请审查当前仓库的未提交改动（`git status` 中所有 staged + unstaged + untracked 文件）。
重点关注：
1. 未提交代码与已有代码的一致性（命名、目录、错误处理风格）
2. 是否引入安全/数据问题（鉴权、SQL 注入、并发、资金流）
3. 是否破坏对外接口契约
你可以使用 `git diff`、`git status`、`rg` 等只读命令收集上下文。
```

## 场景 2：分支对比审查

```
{{通用注入头}}

请审查分支 `{{HEAD}}` 相对 `{{BASE}}` 的全部改动（`git diff {{BASE}}...{{HEAD}}`）。
重点关注：
1. 与 `{{BASE}}` 上既有架构、约定的偏离
2. 是否遗漏测试 / 文档 / 配置同步
3. 是否有 commit 顺序导致的临时不一致状态（中间 commit 存在但被后续 commit 覆盖）
请额外指出：哪些改动属于"无关副作用"应该回滚或拆 PR。
```

## 场景 3：文件夹/路径审查

```
{{通用注入头}}

请审查路径 `{{PATH}}` 下的全部文件（递归）。
重点关注：
1. 模块边界是否清晰，是否有跨层调用
2. 是否存在死代码、重复实现、过度抽象
3. 是否遵守项目约定（参考 `docs/code-conventions/`、`CLAUDE.md` 中的规范）
4. 资金/鉴权/数据持久化等关键路径的正确性
```

## 场景 4：单文件或多文件聚焦审查

```
{{通用注入头}}

请审查以下文件：
{{FILE_LIST，每行一个绝对/相对路径}}

只审查这些文件本身和它们直接调用的关键依赖，不要扩散到无关模块。
```

## 并行审查时的差异化 prompt（可选）

为了让 N 个并行 agent 视角不同、产生互补结论，可以在通用注入头之后加一个"视角"段：

- agent 1（正确性视角）：聚焦逻辑正确性、边界条件、并发、数据一致性、错误处理
- agent 2（安全视角）：聚焦鉴权、注入、信息泄露、CSRF/SSRF、密钥/凭证、资金流
- agent 3（可维护性视角）：聚焦命名、分层、复杂度、重复代码、可测试性、文档

如果用户没指定视角，3 个 agent 跑相同 prompt 也能通过随机性产生重叠+差异，再去重即可。

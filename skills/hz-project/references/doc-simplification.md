# 文档精简策略

> 根据需求复杂度选择合适的文档集，避免简单需求产生过多文档。

## 需求分类与文档策略

### 简单 CRUD（最小文档集）

**判断标准**：
- 单表增删改查
- 无复杂业务逻辑（审批流、状态机、多表关联）
- 交互模式固定（列表页 + 表单弹窗 + 详情弹窗）
- 典型场景：供应商管理、分类管理、标签管理、字典管理

**文档集**：

| 文件 | 是否需要 | 说明 |
|------|---------|------|
| plan.md | ✅ 精简版 | 只需：字段定义、业务规则、枚举值 |
| tasks.md | ✅ 固定模板 | 验收标准固定：创建/编辑/删除/搜索/筛选/启用禁用/查看详情 |
| tech/design.md | ✅ 精简版 | 数据模型 + 角色规划（ui ❌）+ AutoCode 标记 |
| tech/api-contracts.md | ❌ 不需要 | CRUD 接口由框架定义 |
| backend/design.md | ✅ | 数据模型详细定义 |
| backend/tasks.md | ✅ | [autocode] 标记 + 适配任务 |
| frontend/design.md | ✅ 精简版 | 标注"AutoCode 默认样式" |
| frontend/tasks.md | ✅ | 二次适配任务（i18n、枚举、Switch） |
| ui/ | ❌ 全部跳过 | 不产出 merge.html、Resources、设计系统 |
| qa/design.md | ✅ | 使用标准 CRUD 测试模板 |
| qa/tasks.md | ✅ | 固定 9 项测试 |

**plan.md 精简模板**：

```markdown
# 需求计划 — [模块名]管理

## 目标
提供[模块名]的基础数据管理功能。

## 数据字段

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| name | string(200) | 是 | 名称 |
| code | string(50) | 是 | 编码（唯一） |
| ... | ... | ... | ... |

## 业务规则
- [规则1]
- [规则2]

## 枚举值定义

| 字段 | 值 | 含义 |
|------|-----|------|
| status | 1 | 启用 |
| status | 0 | 禁用 |

## 验收标准（固定模板）
- [ ] 创建记录：全字段填写，保存成功
- [ ] 编辑记录：部分字段修改，保存不影响其他字段
- [ ] 删除记录：软删除，列表不再显示
- [ ] 批量删除：选择多条记录批量删除
- [ ] 分页列表：默认按创建时间倒序
- [ ] 搜索筛选：按关键字段搜索
- [ ] 启用/禁用：Switch 切换不影响其他字段
- [ ] 查看详情：展示所有字段信息
```

### 复杂需求（完整文档集）

**判断标准**：
- 多表关联、复杂业务逻辑
- 自定义交互流程（非标准 CRUD）
- 需要独立 UI 设计的页面
- 典型场景：用户认证、数据同步、审批流程、报表统计

**文档集**：全部文件都需要，包括 UI 设计。

### 混合需求

部分模块是简单 CRUD + 部分模块有自定义逻辑。

**策略**：
- CRUD 模块用简单 CRUD 文档策略
- 自定义模块用完整文档策略
- UI 设计只覆盖自定义页面，CRUD 页面跳过
